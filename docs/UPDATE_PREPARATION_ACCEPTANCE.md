# 更新准备阶段超时与诊断修复

日期：2026-11-08。Ops 0.1.22→0.1.23；Agent仍为0.1.8，部署脚本与Skill不变。提交/部署以版本库和发布记录为准。

## 问题与定位

任务页面出现“执行失败，未返回文本日志；请查看错误信息。”。只读检查近期失败任务确认：本次为 Agent 更新，发布 release-25-e01dc59，准备阶段结束后没有执行子任务、文本输出或日志，错误被通用“更新准备失败”替代。

只读验证 Agent 信息请求正常，节点仍运行0.1.7；发布元数据及清单均HTTP200，目标为pipker-agent-0.1.8-linux-amd64。原120秒下载复测在120005ms超时，只收到3,771,042字节，目标文件8,609,954字节。这是制品下载预算不足，不是已经执行节点安装后的失败。

## 改动

- 将制品下载预算设为总计300秒，清单/列表仍120秒。一次请求的所有重定向及正文共用时限；域名白名单、HTTPS、大小限制和SHA-256校验保留，不绕过TLS或使用非可信镜像。
- 准备阶段区分权限、Agent连接、部署登记、清单、制品下载校验、传输、备份及执行创建。
- 失败时持久化明确错误、非空文本诊断及preparationStage/preparationErrorCode。仅输出可识别错误码与已分类业务消息，不将任意驱动异常、URL凭据或签名参数写入任务输出。
- 原历史错误不重写。下载失败没有创建执行子任务，不宣称升级已完成。

## 验证

- 9项相关单元测试通过：可信重定向、重定向总预算、正文超时、次数及大小上限、HTTP失败、安全错误映射与敏感信息排除。
- 原生隔离PostgreSQL回归通过：准备超时后Task为FAILED，日志表可为0条，但output非空，error/result保留阶段；没有产生执行子任务。隔离数据库使用随机loopback端口，未写业务数据库。
- 使用新下载函数只读下载同一真实发布制品，261386ms完整收到8,609,954字节，SHA-256与清单一致。没有写运行缓存，没有上传制品或执行安装、重启。
- lint、类型检查、生产构建通过；此变更没有前端公共组件变动。

复现命令：`npx tsx --test tests/release-download.test.ts tests/update-diagnostics.test.ts tests/agent-connection.test.ts`、`npx tsx --test tests/update-preparation.integration.ts`、`npm run lint`、`npm run check`、`npm run build`。

## 生效与后续操作

新版Ops/Worker生效后，可重新发起Agent0.1.8更新。本轮未自动重试有安装/重启副作用的任务。5分钟仍是有限预算，下载链路进一步变慢时，应改善主控到GitHub发布文件域名的网络并依据新的任务诊断处理。
