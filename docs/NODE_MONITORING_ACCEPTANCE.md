### 改动说明

- Docker inspect 改为序列化完整 State 后解析可选 Health，避免无健康检查字段导致模板失败。仍按准确完整容器 ID 关联；从 Config.Labels 提取 Compose 项目/服务。
- inspect/stats 即使命令部分失败也保留有效 stdout，失败对象独立携带原因；非运行容器的实时 stats 为不适用。无健康检查、未配置 Compose 与采集失败区分，重启次数 0 不丢失。
- vda1 等分区通过 sysfs 实际父路径读取父盘 diskseq，并组合分区号、起始扇区、boot_id。父世代、起始扇区或启动改变会断开基线；没有可靠身份仍保持 null，不按设备名称推断父盘。旧内核无 diskseq 仍可能不支持速率。
- 可选的系列 status/reason 区分九种可用性；首个 CPU/速率样本明确等待基线，无法读取设备身份显示不支持。未返回的主要主机指标仍在页面出现；缺失不补零，历史聚合继续保留 null。
- 文件系统使用量读取失败保留对应挂载点和错误，不影响其他挂载点。分类错误列表限制为协议上限并报告截断。
- 分类诊断显示采样时间、最近完整成功时间、耗时、失败原因、截断与处理建议。最近成功时间存入已有快照 JSON，无数据库结构迁移；旧记录没有成功时间时不编造成功记录。
- 影响版本：Ops 0.1.20、Agent 0.1.6；部署脚本和 Skill 未变更。
